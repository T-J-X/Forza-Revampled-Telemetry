# Scaffold baseline

This is the live bench of a scaffold dash (HyperbolicTiles, catalog row 72, still a scaffold), the baseline for the rule that a dash's own CPU share is at most 0.3 ms over a scaffold. Measured 2026-11-28 06:18:36 to 06:19:45 UTC on this PC at commit 2d1f114, with `mock-udp --scenario bmw_m4_cs --port 8000 --duration 100` streaming and `FH6_WheelDash --demo --cluster HyperbolicTiles --stats --bench-seconds 60 --bench-out docs/perf/scaffold-baseline.md` (release build). A dash thread compares its own live bench (same command, its own `--cluster`) with this file when no scaffold is left to bench beside it.

## Against the targets

- Receive-to-present under one display frame (3.33 ms): p99 1.405 ms: **met**
- Under 1 ms CPU per frame: p99 0.927 ms: **met**

Indicative only (derived from DWM timing, not a target): 77.7% of new packets were presented before the first vblank after they arrived (2719 of 3498); the rest were shown one refresh later. DWM's reported vblank time can lag on a mostly idle desktop, so this estimate can read low. Either way no packet ever waits behind another: there is no queue.

Notes:
- Times are measured with `Instant`. "Receive" is when `recv_from` returned on the UDP thread; "present returned" is when `Queue::present` returned on the render thread.
- The vblank columns use DWM's composition timing (`DwmGetCompositionTimingInfo`) at present time. Waiting for the vblank is not engine work: it is set by the display refresh. Scan-out of the composed frame can add up to one more refresh on some display paths, which this method cannot observe.
- Only frames that showed a new packet count towards the receive series; CPU time counts every presented frame.
- "CPU per frame" is the render thread's whole iteration for a presented frame, from its wake to the end of the frame, less the frame-latency wait: the loop's checks, building the frame, drawing the scrim, the cluster and the OSD into the kit's arena, the kit's render and submit, `present` and the kit's staging hand-back. The rows under it are its parts; the small rest is the sample bookkeeping.
- No frame was idle-dimmed. To measure a parked car, run `mock-udp --scenario parked` and a bench longer than the 30 s idle wait (`--bench-seconds 60`).

## Reproduce

```
cargo build --release -p fh6-app -p mock-udp
target/release/fh6-stand-in   (focused, full screen)
target/release/mock-udp --scenario bmw_m4_cs --duration 90 --rate-hz 60
target/release/FH6_WheelDash --game-process fh6-stand-in.exe --bench-seconds 60 --bench-out docs/perf/engine.md
```
